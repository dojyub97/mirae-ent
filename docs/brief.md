# 프로젝트 브리프

이비인후과 홈페이지 제작 프로젝트의 기준 문서다. 사용자와 합의한 내용만 적는다. 합의하지 않은 내용은 "미정"에 둔다.

## 결정됨

### 프로젝트와 역할
- 고객: 운영 중인 이비인후과. 원장님은 사용자의 아버지다.
- 제작: 사용자가 전적으로 의뢰받아 맡는다.
- 원장님: 각 페이지 원고의 검수와 피드백만 하신다.
- 현재 병원 홈페이지는 없다.

### 결과물
- 홈페이지. 의료 콘텐츠 중심이며, 랜딩페이지 형식의 여러 페이지로 구성한다.
- 방문자는 외부 고객(환자)이다.
- 방문자가 해주길 바라는 행동:
  - 전화 문의, 내원
  - 병원에 대한 신뢰 형성
  - 건강 정보 얻기

### 내세울 진료 분야
- 수술 전문
- 고압산소치료
- 수액
- 코 (비염, 축농증, 비중격)
- 귀 (중이염, 난청, 어지럼증)
- 목 (편도, 음성, 갑상선)
- 수면 (코골이, 수면무호흡)

### 메뉴에 들어갈 페이지
- 병원 소개, 의료진
- 진료분야별 페이지
- 특화 클리닉
- 시설, 장비 소개
- 상세 구조는 사용자의 IA(information architecture) 파일을 기준으로 정한다.

### 원고
- 사용자와 Claude가 초안을 함께 쓰고, 원장님이 검수한다.
- Claude가 혼자 초안을 쓰지 않는다.

### 디자인 방향
- 전문적이고 신뢰감을 준다.
- 대학병원처럼 딱딱하지 않다.
- 깔끔하고 모던하다.
- 이 조합 때문에 레퍼런스의 일관성이 떨어지면 다시 논의한다.

### 레퍼런스 방식
- 사용자와 Claude 양쪽이 각자 조사한다.
- 병원 사이트와 병원이 아닌 사이트 모두 대상이다.
- 사이트 하나를 따라 하지 않고, 사이트마다 필요한 부분을 골라 조합한다.

### 기기
- 모바일 우선이다.
- 반응형으로 만들고, PC에서도 자연스러워야 한다.

### 유입 경로
- 네이버 검색
- 구글 검색
- 네이버 플레이스, 지도

### 보유 자료
- 병원 로고
- 병원 사진
- 원장님 사진, 약력
- 원장님 진료·수술 컨셉 사진

### 운영
- 도메인을 구매하고, 비용은 최소로 한다.
- 오픈 후 수정할 일은 없다(휴진 공지, 진료시간 변경 등 포함).

## 미정

- 사이트 상세 구조: 사용자가 IA 파일을 업로드할 예정이다.
- 색상
- 레퍼런스 선정: 조사 시작 시점은 사용자가 정한다.
- 기술 스택
- 호스팅 서비스
- 도메인 주소
- 병원 기본 정보: 병원명, 주소, 전화번호, 진료시간 등
- 특화 클리닉별 세부 내용: 수술 전문의 범위 등
- 각 페이지 원고
- 의료광고 규정 검토 기준: 의료법상 금지 표현을 점검하는 기준
- 사진 자료 관리 방식: 원본은 커밋하지 않는다. 웹용 사진을 어떻게 다룰지는 미정이다.
- 검증 방법과 판단 기준
- Claude에게 맡길 범위

## 하지 않을 것

- 개발 지식이 필요한 기능
- 지금 단계에서 색상 확정: 남색 등 특정 색으로 미리 고정하지 않는다.
- 대학병원처럼 딱딱한 디자인
